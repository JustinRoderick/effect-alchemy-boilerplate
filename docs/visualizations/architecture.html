Effect + Alchemy boilerplate: architecture

How a project built from this boilerplate is laid out, how its layers fit together, and how a request moves through it. The layout combines the structure of Effect's own repo, Alchemy's file-layout guide, and t3code's production Cloudflare Worker (infra/relay).

2. Dependency rules

Imports flow one way, toward @app/contracts. Only alchemy.run.ts reaches into apps/*, and it does so to deploy them.

  • contracts holds wire types: Schema models, branded IDs, Schema.TaggedError, HttpApi/RpcGroup. It does no I/O and has no runtime logic.
  • shared exists only once two packages need the same pure helper. It uses subpath exports and no barrel.
  • apps never import each other. The web app's types for the API come from contracts, through HttpApiClient.make(AppApi).
  • alchemy.run.ts is the only file that imports from apps/*, and only the Worker class it deploys.
  • All packages export ./src/*.ts directly, so no build step is needed (as in t3code and Alchemy).

4. Worker phases

The Worker's outer generator (Construction) runs twice: once when you deploy, and once per cold start. The inner fetch runs per request. The rules for Config, bindings, and resources follow from this.

Expected error → typed channel

return yield* new TodoNotFound({ id }) stays in E all the way up. Because the contract declares it with { httpApiStatus: 404 }, the client receives a typed TodoNotFound. Handle it with Effect.catchTags.

Infrastructure failure → defect

A SqlError or SchemaError in TodoRepo becomes a defect (Effect.orDie), so domain interfaces only list errors a caller can act on. HTTP turns defects into 500s, and the span records the cause.

6. Anatomy of a service module

One file per service, always in the same order. This is the shape of t3code's WorkspacePaths.ts and the relay's Devices.ts.

import type { CreateTodo, Todo } from "@app/contracts/todos";
import * as Context from "effect/Context";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Schema from "effect/Schema";
import * as AppConfig from "../AppConfig.ts";
import * as TodoRepo from "./TodoRepo.ts";
export class TodoLimitReached extends Schema.TaggedError<TodoLimitReached>()(
  "TodoLimitReached",
  { limit: Schema.Number },
) {
  override get message() { return `Todo limit of ${this.limit} reached.`; }
}
export class Todos extends Context.Service<
  Todos,
  {
    readonly create: (input: CreateTodo) => Effect.Effect<Todo, TodoLimitReached>;
  }
>()("@app/api/todos/Todos") {}
const make = Effect.gen(function* () {
  const repo = yield* TodoRepo.TodoRepo;      // deps via yield*, never params
  const config = yield* AppConfig.AppConfig;

  const create: Todos["Service"]["create"] = Effect.fn("Todos.create")(function* (input) {
    const existing = yield* repo.list;
    if (existing.length >= config.maxTodos) {
      return yield* new TodoLimitReached({ limit: config.maxTodos });
    }
    // ...
  });

  return Todos.of({ create });
});
export const layer = Layer.effect(Todos, make);
  1. Namespace imports, one module at a timeWrite import * as Effect from "effect/Effect". Import your own services the same way, then use TodoRepo.TodoRepo and TodoRepo.layer.
  2. Errors firstUse Schema.TaggedError with bounded attributes. Build the message from those attributes, never from cause. Wrap underlying failures in cause: Schema.Defect().
  3. The tag, with its interface inlineDon't write a separate TodosShape; refer to the type as Todos["Service"]. Give the tag an id like "<pkg>/<path>/<Name>".
  4. makeGet dependencies with yield* so the layer's type lists them. Each method is Effect.fn("Service.method"), which gives you a span. Return Tag.of({...}).
  5. layerUse layer for the primary implementation, and layerTest, layerMemory, or layer<Adapter> for variants. Keep make private unless another module imports it, since knip fails on unused exports.
